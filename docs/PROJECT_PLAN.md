# 肥鱼电台 FishFM — 开发路线

更新：2026-09-27。状态：**Phase 1 离线控制核心已实现并通过本机验证；Phase 0 宿主、平台与播放实验尚未通过。**

本文件是任务顺序、状态和跨设备交接的唯一入口。产品规则见 [MVP](MVP.md)，技术设计见 [架构](ARCHITECTURE.md)，验证细节见 [Phase 0](PHASE_0.md)，来源和取舍见 [决策记录](DECISIONS.md)。

推进原则：尽早做出一个可运行的真实播放闭环，再扩大能力。不要先把完整人格引擎写完，才第一次接入真实 DSH 和平台。技术样例先消除不确定性，正式实现再补足可靠性与交付要求。

## 任务拆分与依赖

表中的 A01～A10 对应 [MVP 验收清单](MVP.md)。完成后在本表标注状态和证据链接，不另建一份重复进度表。

### Phase 0：先确认可以怎么实现

执行顺序：P0-01 DSH → P0-04 播放宿主基础 → P0-02 网易云 → P0-03 QQ → 补齐 P0-04 真实平台生命周期实验 → P0-05 桌面 → P0-06 数据 → P0-07 运行边界。

P0-04 先用自有或可合法使用的短音频测试进程生命周期，再用平台音频复测；避免“等 Provider 才能测播放器、等播放器才能测 Provider”的循环依赖。P0-02/03 可以先记录接口结果，真实声音验证仍依赖播放宿主。

每个实验只回答 [Phase 0 清单](PHASE_0.md) 中的问题。近期记录接口一轮验证失败后，先证明收藏/歌单 fallback 可用；除非新证据表明可行，不重复投入同一路径。登录、真实播放或 DSH 接入失败则保留阻塞状态。

阶段结论必须明确：实际 DSH 版本、事件与命令入口、Core/Playback 的宿主、静音进度方案、IPC、凭据存储、数据库、语言/包管理器及必要原生工具链。原型能证明接口后，才固化这些选择。

**第一个可运行成果是 P3：** 用户能在自己的 DSH 环境中控制网易云真实播放。它是开发预览，不是 v0.1 发布。P4 完成前不把单平台成果称为双平台 MVP。

P2 和 P4 都必须使用同一组规范化契约检查；真实账号检查与离线 CI 分开，不让 CI 依赖私人 Cookie、短期播放地址或平台在线状态。

## 关键依赖与推进边界

```text
Phase 0 关键结论
  → F1 → F2 → F3 → F4
  → P1/P2 → P3 网易云首条真实闭环
  → P4 QQ → P5 双平台协调
  → T1 → T2 → T3 人格成长
          └→ I1 DSH 完整适配
     P5 → U1 → U2 完整桌面体验（同时依赖 T3/I1）
  → R1 → R2/R3 → R4
```

可以在部分实验等待账号授权时推进无依赖的契约或离线样例，但阶段仍保留未完成状态。任何生产实现所依赖的关键技术结论未通过时，不先写死对应 SDK、IPC 或播放后端。

不按未经验证的工期承诺完成日期。Phase 0 结束后根据实际接口和打包结果再估算；每个任务控制为一个可独立验证、可审查的改动，过大时拆子任务而不扩大范围。

## 验证策略

| 层次 | 要验证的风险 | 执行时机 |
|---|---|---|
| 本地规则测试 | 暂停被撤销、旧请求覆盖、重复累计、探索/禁播失效 | F2 起；修改相关行为时执行 |
| 契约与存储集成 | 平台结果不一致、事务/迁移失效、IPC 重连状态倒退 | 对应适配器、持久化和桥接实现时 |
| 真实账号与音频检查 | 可登录但不能播放、权限/URL 失效、降级来源误报 | P3/P4 及对应接口变动时 |
| 桌面与宿主检查 | UI 退出带走音频、DPI/多屏位置丢失、DSH 阻塞 | U1/U2、R1/R3 |
| 持续运行 | 音乐新增 LLM 请求、资源持续增长、历史失真 | R2；影响上述结果的后续修复需要重新验证 |

不为静态文档或简单可逆改动堆测试。固定种子可验证选择轨迹，不能用少量抽样结果要求探索比例恰好等于设置值。文档中的参数仍待调，首次实现时记录数值、理由和验证数据。

## 跨设备交接与任务完成定义

每次接续先看本文件的任务状态和前置条件，再读取关联规格。开发分支采用 `codex/<任务简名>`；同一任务在两台设备之间串行交接，避免同时修改同一分支。

每项任务完成时：更新状态，附实现 commit/PR、实际运行命令、结果和剩余限制；如有行为或接口变更，同步 MVP/架构/决策记录。提交相关文件并推送开发分支后，另一设备才能接续。合并后让 `main` 保持可检查、可复现；不自动合并未完成改动。

## 紧接着要做的工作

1. 确认实际使用的 DSH 仓库、版本和插件接口，记录可运行的最小事件适配样例。
2. 优先验证用户日常使用的网易云；同时保留 QQ 为同一版本的必交付项。
3. 验证真实音频播放能否脱离可见 UI 存活，再确定 Playback 与 Tauri 的宿主方式。
4. 核实参考项目及许可证，最后依据实测结果搭代码目录和依赖。

当前没有需要用户重新决定的产品范围。账号授权等验证所需输入，在实验准备就绪时再提出；不得把未登录或未执行的项目标成通过。

## 阶段内降级与发布边界

- 近期记录不足：使用平台收藏、用户歌单或插件已有历史补足，展示真实来源与数量；不足 200 首仍可运行，不伪造记录。
- 某平台的推荐不可用：退回熟悉池，记录本次没有发生探索。
- UI 暂时不可用：允许继续验证 Core 和播放服务；不代表包含悬浮窗的 v0.1 已交付。
- QQ 登录/搜索/真实播放无法通过：可以交付技术进展，不能称为双平台 MVP 完成。
- Windows 为首轮验证环境；其他系统尚未承诺兼容，待验证后再记录支持范围。
