# 项目规划

更新：2026-09-27。状态：**文档已整理，Phase 0 未开始，代码尚未实现。**

本文件只维护路线和进度。产品范围见 [MVP](MVP.md)，技术设计见 [架构](ARCHITECTURE.md)，验证任务见 [Phase 0](PHASE_0.md)，来源和取舍见 [决策记录](DECISIONS.md)。

## 交付顺序

| 阶段 | 交付物 | 完成条件 | 状态 |
|---|---|---|---|
| 0 技术验证 | DSH、网易云、QQ、独立播放、透明小窗的最小样例及证据 | 明确可用接口、失败路径、进程边界和必要降级 | 未开始 |
| 1 本地核心 | 用户环境、Agent 偏好、SQLite、策略、队列、两套开关、探索 | 固定数据可验证用户优先、暂停保持、去重、偏好更新和断点恢复 | 未开始 |
| 2 双平台闭环 | 两个自维护 Provider 与独立 Playback 服务 | 各平台真实完成登录、导入、搜索、播放、暂停、恢复、下一首 | 未开始 |
| 3 DSH 与桌面集成 | 事件适配、命令入口、默认角色、悬浮控制、托盘恢复 | 隐藏/关闭窗口不影响音乐，故障不阻塞 DSH | 未开始 |
| 4 验收与交付 | 本地安装产物、使用说明、已知限制、验收记录 | MVP 所有验收项完成，包括两小时零新增 LLM 请求 | 未开始 |

Phase 0 的样例用于验证关键路径；后续阶段将已经验证的路径整理为正式实现。单个样例成功不等于该模块完成。

## 下一步

1. 确认实际使用的 DSH 仓库、版本和插件接口，记录可运行的最小事件适配样例。
2. 优先验证用户日常使用的网易云；同时保留 QQ 为同一版本的必交付项。
3. 验证真实音频播放能否脱离可见 UI 存活，再确定 Playback 与 Tauri 的宿主方式。
4. 核实参考项目及许可证，最后依据实测结果搭代码目录和依赖。

当前没有需要用户重新决定的产品范围。账号授权等验证所需输入，在实验准备就绪时再提出；不得把未登录或未执行的项目标成通过。

## 阶段内降级与发布边界

- 近期记录不足：使用平台收藏、用户歌单或插件已有历史补足，展示真实来源与数量；不足 200 首仍可运行，不伪造记录。
- 某平台的推荐不可用：退回熟悉池，记录本次没有发生探索。
- UI 暂时不可用：允许继续验证 Core 和播放服务；不代表包含悬浮窗的 v0.1 已交付。
- QQ 登录/搜索/真实播放无法通过：可以交付技术进展，不能称为双平台 MVP 完成。
- Windows 为首轮验证环境；其他系统尚未承诺兼容，待验证后再记录支持范围。
