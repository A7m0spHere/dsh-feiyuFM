# 肥鱼电台 FishFM — 开发路线

更新：2026-09-29。状态：**Phase 1 离线控制核心已实现；新增 DSH 主界面内嵌设置面板，已验证 0.2.0-rc.1 页面下发与真实设置 API；浏览器视觉点击验收受阻。独立音乐悬浮窗、平台闭环仍未完成。**

本轮增量：主侧栏与设置窗口均注册“肥鱼电台”，使用已有 Core 保存设置；网易云新增扫码、DPAPI 凭据持久化、状态轮询与导入入口。没有新增模型工具或模型请求。宿主验证与限制见 [U3 主界面设置](spikes/U3-dsh-settings.md) 与 [U4 快捷登录](spikes/U4-quick-login.md)。QQ 接口和真实账号闭环仍未验。U2/A07 仅新增内嵌面板部分实现，不据此将独立桌面窗口或全部验收标为完成。

依赖增量：`qrcode@1.5.4` 从开发依赖改为运行依赖，给 Core 本地生成登录二维码 PNG Data URL；版本与许可不变，未新增安装包。

本文件是任务顺序、状态和跨设备交接的唯一入口。产品规则见 [MVP](MVP.md)，技术设计见 [架构](ARCHITECTURE.md)，验证细节见 [Phase 0](PHASE_0.md)，来源和取舍见 [决策记录](DECISIONS.md)。

推进原则：尽早做出一个可运行的真实播放闭环，再扩大能力。不要先把完整人格引擎写完，才第一次接入真实 DSH 和平台。技术样例先消除不确定性，正式实现再补足可靠性与交付要求。

## 任务拆分与依赖

表中的 A01～A10 对应 [MVP 验收清单](MVP.md)。完成后在本表标注状态和证据链接，不另建一份重复进度表。

### Phase 0：先确认可以怎么实现

执行顺序：P0-01 DSH → P0-04 播放宿主基础 → P0-02 网易云 → P0-03 QQ → 补齐 P0-04 真实平台生命周期实验 → P0-05 桌面 → P0-06 数据 → P0-07 运行边界。

P0-04 先用自有或可合法使用的短音频测试进程生命周期，再用平台音频复测；避免“等 Provider 才能测播放器、等播放器才能测 Provider”的循环依赖。P0-02/03 可以先记录接口结果，真实声音验证仍依赖播放宿主。

每个实验只回答 [Phase 0 清单](PHASE_0.md) 中的问题。近期记录接口一轮验证失败后，先证明收藏/歌单 fallback 可用；除非新证据表明可行，不重复投入同一路径。登录、真实播放或 DSH 接入失败则保留阻塞状态。

阶段结论必须明确：实际 DSH 版本、事件与命令入口、Core/Playback 的宿主、静音进度方案、IPC、凭据存储、数据库、语言/包管理器及必要原生工具链。原型能证明接口后，才固化这些选择。

## 关键依赖与推进边界

```text
Phase 0 关键结论
  → F1 → F2 → F3 → F4
  → P1/P2 → P3 网易云首条真实闭环
  → P4 QQ → P5 双平台协调
  → T1 → T2 → T3 人格成长
          └→ I1 DSH 完整适配
     P5 → U1 → U2 完整桌面体验（同时依赖 T3/I1）
  → R1 → R2/R3 → R4
```

可以在部分实验等待账号授权时推进无依赖的契约或离线样例，但阶段仍保留未完成状态。任何生产实现所依赖的关键技术结论未通过时，不先写死对应 SDK、IPC 或播放后端。

不按未经验证的工期承诺完成日期。Phase 0 结束后根据实际接口和打包结果再估算；每个任务控制为一个可独立验证、可审查的改动，过大时拆子任务而不扩大范围。

## 跨设备交接与任务完成定义

每次接续先看本文件的任务状态和前置条件，再读取关联规格。开发分支采用 `codex/<任务简名>`；同一任务在两台设备之间串行交接，避免同时修改同一分支。
