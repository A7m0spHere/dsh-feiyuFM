# #7 首轮真实推荐质量基线

记录日期：2026-11-01（Asia/Shanghai）。对应 [Issue #7](https://github.com/A7m0spHere/dsh-feiyuFM/issues/7)；最新状态和工程验证统一维护在 [PROJECT_PLAN](../PROJECT_PLAN.md)，操作方法见 [研究说明](README.md)。

## 方法与来源

本轮从用户本机数据库以 `DatabaseSync({readOnly:true})` 在同一读事务中冻结一批已保存的网易云候选、参考歌曲、筛选结果及其账本。没有启动 Core、平台请求、模型或播放器，没有修改用户偏好、预算、播放规则或原数据库。采样时看到的 83 条已完成筛选账本不等于 83 份研究样本：历史入选名单没有逐批完整保留，本轮只使用一份可与账本和候选归属核对的完整批次。

| 项目 | 本轮值 |
|---|---|
| 样本类型 | `local-snapshot`，一批真实历史结果；目录元数据仅留本机 |
| 批次完成时间 | 2026-11-01 15:19:39.675 +08:00 |
| 冻结时间 | 2026-11-01 15:35:44.122 +08:00 |
| 输入 SHA-256 | `d991189f0a44ae022063c2fc890e84e8710fd67cc082fe64a1938f86b6a8c84a` |
| 导出工具基线 | `7f62f84`；原调用所加载的插件提交未知，不由采样工具版本反推 |
| 评价工具 | [`6e161b0`](https://github.com/A7m0spHere/dsh-feiyuFM/commit/6e161b0f26771a89c24f51a3c424a4631c3b81be)；Windows / Node 24.22.1 |
| 候选与入选 | 4 首候选，1 首入选，4 首参考曲 |
| 固定参数 | `top-k=6`；不足六首按实际数量报告，不补入其他批次 |
| 比较对象 | 已保存 LLM 排名与 `distinct-artist-first`，共同排除后均只有同一首 |

回放将已保存 `picks` 重建为响应，经生产 `finishSummary` 解析；这不是原始模型文本重放、模型重新推理或完整 Core 自动播放顺序复现。用户指令、本地评分、冷却和随机选择等没有被重建。两次不含反馈的回放在同一输入和参数下得到一致的 JSON 报告、Markdown 报告和评价表；纳入反馈后仍使用同一输入 hash。

`newDiscoveryJudged=1` 的分母仅含同时给出明确评价和是否听过的曲目；唯一评价为“一般”，未达到“此前未听过且愿再听”的分子条件，因此新发现数为 0。“一般”不等于“不喜欢”，也不等于愿意保存或继续听。上述单曲比例只描述本次回答，不能外推整体推荐质量。

历史 `known=true` 表示调用前存在相同歌曲键的有效进度记录；用户 `heardBefore=false` 表示本人认为以前没有听过。两者口径不同，保留各自来源，不覆盖快照或自动修正用户评价；具体差异原因未知。人工 `played` 来自用户自报，本轮没有另行验证该次播放的取链、音频或宿主耗时。

## 分析与后续依据

- 原排名与研究变体完全相同，只有一首入选，本次无法判断艺人优先重排的收益；生产策略保持不变。
- 入选曲被评为“一般”，同时理由被认为可信。理由可信与歌曲命中喜好是两个独立结果，不把其中一个代替另一个；用户认可理由也不构成音频相似性或模型听感的证明。
- 另外三首未被评价，未保留模型拒绝原因，因此无法判断是否漏选，也无法将问题归因为平台召回、模型筛选或用户偏好不足。4 候选／1 入选本身不足以证明供给瓶颈的原因。
- 按“未听过且愿再听、来源与理由可核对、没有已知不可播”的研究建议，本次没有已确认的分享候选；这不启动主动分享功能。
- 后续优先利用正常使用自然产生的较完整批次，继续冻结同批材料、扩大明确评价覆盖，再判断是否提出 #9/#10 的小范围实现。保留最近 50 次硬窗口和既有预算，不为研究增加调用。

本报告仅是一轮单批、单曲人工反馈，不计入 #11 连续试用人数、时长或完成记录，不提升 A01–A10 的完整验收。历史短窗重复指标不作为 N26 最近 50 次实际开始的硬窗口验收。按本轮约定，#7 保持打开。

原始快照、歌曲与艺人、参考曲、反馈文件和工具来源记录只保存在本机忽略目录；本报告只提交匿名汇总。后续回放必须使用该冻结输入和对应反馈，不重新导出最新批次后沿用旧评价。
