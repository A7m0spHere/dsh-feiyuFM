## 方法与来源

首轮从用户本机数据库以 `DatabaseSync({readOnly:true})` 在同一读事务中冻结一批已保存的网易云候选、参考歌曲、筛选结果及其账本。没有启动 Core、平台请求、模型或播放器，没有修改用户偏好、预算、播放规则或原数据库。采样时看到的 83 条已完成筛选账本不等于 83 份研究样本：历史入选名单没有逐批完整保留，首轮只使用一份可与账本和候选归属核对的完整批次。后续按用户要求补做输入审计和第二个自然批次复核，分别见下文；两批快照与评价独立保存。

| 批次完成时间 | 2026-11-01 15:19:39.675 +08:00 |

## 分析与后续依据

- 原排名与研究变体完全相同，只有一首入选，本次无法判断艺人优先重排的收益；生产策略保持不变。
- 入选曲被评为“一般”，同时理由被认为可信。理由可信与歌曲命中喜好是两个独立结果，不把其中一个代替另一个；用户认可理由也不构成音频相似性或模型听感的证明。
- 未入选的 c004 被用户评为“愿再听且此前没听过”，形成一条明确的筛选遗漏线索；同批入选曲为“一般”。这说明本批平台候选中存在正向评价曲目，尚不能断言模型筛选整体变差，也不能根据单条反馈确定拒绝原因。
- `distinct-artist-first` 只重排已入选集合，不能补回未入选的 c004。本轮下一步的研究重点是核对筛选事实与选择门槛，单纯重排不覆盖该线索；未保存的模型拒绝原因保持未知，4 候选／1 入选也不足以证明供给瓶颈的根因。
- c004 可作为后续核查的发现线索，但模型理由缺失、实际播放和权限未知，不记为已确认的分享候选；这不启动主动分享功能。
- 后续优先利用正常使用自然产生的较完整批次，继续冻结同批材料、扩充跨批次样本，检验正向评价候选未被保留的现象是否重复，再判断是否提出 #9/#10 的小范围实现。保留最近 50 次硬窗口和既有预算，不为研究增加调用。

上述首轮是单批四曲人工反馈，覆盖该批全部候选，但不计入 #11 连续试用人数、时长或完成记录，不提升 A01–A10 的完整验收。历史短窗重复指标不作为 N26 最近 50 次实际开始的硬窗口验收。先前保留 #7 打开的阶段约定，随后由用户“按顺序推进直到关闭”的明确指令修订；最终依据见下文“研究结项”。

原始快照、歌曲与艺人、参考曲、反馈文件和工具来源记录只保存在本机忽略目录；本报告只提交匿名汇总。后续回放必须使用该冻结输入和对应反馈，不重新导出最新批次后沿用旧评价。

## 筛选输入与选择门槛审计

2026-11-01 以 `a969553` 的源码规则只读核对两批原始账本。审计汇总、来源版本和指标见 [匿名结构化证据](assets/ISSUE_7_FILTER_AUDIT_20261101.json)。原始提示词、歌曲键和审计脚本保存在本机忽略目录，不进入公开附件。

| 核对项 | 结果与证据边界 |
|---|---|
| 最终候选是否遗漏 c004 | 两批账本都包含对应歌曲键，分别与冻结快照核对；c004 都未入选，最终输入没有先丢掉它 |
| 事实是否对应实际预留输入 | 从账本去掉本地 `candidateRevision/candidateOwner/localCandidates`，重建用户提示词，再按生产规则计算 `SHA256(SHA256(prompt) + '|' + candidateRevision)`；两批均与原 `fact_hash` 一致 |
| 候选字段 | 两批均为 `i/key/title/artist/from`，没有逐曲 `feedback`、流派或音频特征。未记录逐曲反馈不等于传递故障；本次研究评价发生在调用之后，且没有写入产品偏好 |
| 标题和艺人裁剪 | 与各自账本保存的 `localCandidates` 比较，四首候选的标题、艺人均未在事实投影中再次截断。来源端更早的处理未据此补验 |
| 参考歌曲与偏好覆盖 | 两批各保存四首参考曲和聚合口味；当前实现仅取前四首参考曲，并限制文字长度。原始完整参考库与当时的代表性没有保存，不能宣布完整偏好均已传入 |
| 输入字节限制 | 当前模板下重建的系统提示词加用户提示词分别为 1380、1371 bytes，低于当前 2600-byte 限制；c004 在最终事实列表中，不能把它的未入选归因为本次已观察到的输入丢失 |
| 可选首数和输出额度 | 用当前生产模板及预留公式反算，两批唯一一致解均为输出额度 2560、最多选择 12 首；这与记录的预留额 4964、4955 相符，不支持“固定只能选一首”的解释。原系统提示词、输出配置和已加载插件提交未直接保存，反算是有条件重建，不冒充原始配置实录 |
| 解析器是否硬性拒绝 c004 | 使用明确标记为 `synthetic` 的内存回放，将同一候选作为唯一合法序号返回，生产解析器可以接受；只验证解析路径，不算真实模型选择或质量提升 |
| 为何拒绝该曲 | 结果协议只保存入选项及其理由，没有拒绝理由，无法还原模型为什么没有选择 c004 |

本轮未发现可复现的“c004 未进入模型”或“解析器固定剔除该曲”的实现缺陷。仅凭这些输入和少量评价，不将原因断言为模型保守、预算不足或参考曲采样错误；相应未知边界保留。

## 研究结项

本次完成了原 #7 要求的指标定义、固定输入可复现对照、失败与成本记录、至少一轮真实人工反馈，以及“没有可验证收益则保留现策略”的决策。其后追加的输入与门槛审计、第二自然批次人工复核也已完成。此前待办中的“更大批次”未实际获得，不能记作较大样本验证；两批、一个评价者、五首不同歌曲和八条候选评价是本次实际边界，不是八份独立样本或整体质量验收。

结论为 **`keep-current-production-policy`**：两批中的 `distinct-artist-first` 都与原名单相同，没有可验证的重排收益；c004 的线索也不由入选后重排解决。没有足够证据上线新的筛选或探索算法，本次不调整生产权重、预算、暂停／禁播或最近 50 次硬窗口。

按用户最新要求，本次以“推荐质量研究已完成、原策略保留”收束 #7，不以“推荐质量已经提升”或“精确拒绝原因已查明”关闭。更广的长期真实体验继续由 #11 承接；#10 仅在后续样本证明有收益时提出独立增量。未获得的更大批次、供应商内部重试、未知播放权限、未保存拒绝理由等均作为限制保留，不恢复为本项无期限等待门槛。原始研究回归、当前针对性复核和文档检查的实际范围统一看 PROJECT_PLAN。
