# #9 用户偏好信号：来源、优先级与固定输入对照

对应 [Issue #9](https://github.com/A7m0spHere/dsh-feiyuFM/issues/9)。实施状态与未验项只在 [PROJECT_PLAN](../PROJECT_PLAN.md) 维护。本文解释现有 schema 和决策路径；不是新增情绪识别或长期记忆系统。

## 三类数据的所有权

| 数据 | 存储与读取 | 代表什么、怎样更正 |
|---|---|---|
| 用户输入环境 | `user_environment/environment_sources`；[environment.mjs](../../src/environment.mjs) | 来源为 recent/liked/playlist/plugin_history，保留真实数量和未知字段；可重导入、清空。平台收藏来源不等于用户在插件里的显式评分 |
| 用户明确反馈及硬约束 | `user_track_feedback/constraints`；[feedback.mjs](../../src/feedback.mjs)、[core.mjs](../../src/core.mjs) | +1 喜欢、-1 少推荐、0 撤销；禁播单独存约束。反馈是用户规则，不覆盖 Agent 的 affinity。撤销反馈不解除禁播，反过来也不等价 |
| Agent 自主经历 | `agent_preferences/listen_history/growth_jobs/session_influence`；[taste.mjs](../../src/taste.mjs)、[growth.mjs](../../src/growth.mjs) | 自主有效进度产生的有界倾向，含来源与时间；不是用户“明确喜欢”的替身。可重置、在单个检查点范围内撤销；时间衰减不是新证据 |

已有设置与字段足够表达本轮语义，没有新增数据库字段、迁移或独立“用户人格”表。表达风格由 [U20](../spikes/U20-expression-style-prototype.md) 独立保存；[U21](../spikes/U21-feedback-management.md) 增加历史反馈管理，不改变本表的评分权重和数据所有权。

## 信号语义表

这里的强弱是证据含义，不是统计置信概率；不把未观测的信息补成 0 或负面偏好。

| 输入信号 | 来源与可信范围 | 当前应用、边界与更正 |
|---|---|---|
| 插件内喜欢 | 用户对当前播放实例的明确操作 | 本地加 0.25，进入喜欢曲查询并可作相似种子；给模型候选 `feedback=liked`。不增加收听次数，不推断喜欢整个艺人；撤销置 0 |
| 插件内少推荐 | 用户对当前播放实例的明确操作 | 本地减 0.75，退出种子；给模型候选 `feedback=reduced`。仍可点播、仍可能是唯一候选；不是禁播或“不喜欢所有相关风格”。可撤销 |
| 禁播 | 用户硬约束 | 评分之前排除，模型顺序和喜欢均不能覆盖；用取消禁播更正，而不是加分抵消 |
| 主动点播 | 用户当前选择 | 是一次播放命令；不自动写显式评分，不作为 Agent 自主成长。不能把一首点播推断为长期喜好 |
| 用户请求下一首 | 用户要求换歌，由推荐器选曲 | 有效自主经历按真实进度处理，触发换曲本身不写负分；短于门槛的跳过不成长 |
| 达门槛后跳过 | 已有足够的 Agent 有效进度 | 可产生最多正常完成一半的非负成长；不是讨厌。只说明此前已有弱正向经历，不推断跳过原因 |
| 暂停／播放失败 | 控制状态／故障 | 暂停本身不增加进度，失败不作为偏好信号；既有成功进度与命令分别处理，不反向打负分 |
| 静音自主听歌 | listening=true，真实 Agent 有效进度 | 可成长但权重 0.6、曲目来源 `listen_silent`；不是用户听到了声音，不是“完全没有经历”。listening=false 则不成长 |
| 自然有效完成 | Agent 选曲与真实进度 | 达到 30 秒或已知时长一半（取较小值），单次步长上限 0.03、收益递减；不把选中本身算成长，也不证明用户本人喜欢 |
| 临时 Session | 实际宿主 Session 标识和瞬态标记 | 临时权重 0.5；同一 Session 对同一曲最多 8 次更新，额度持久化。不是新增“心情”字段；实际会话分类可信度仍依赖宿主事件，不冒充现场已验 |
| recent/收藏/歌单导入 | 平台给出的来源、频次和时间 | 环境与初始化的有限依据，只补缺失偏好，不覆盖后续成长。缺字段保持未知，不混称近期记录 |
| 当前情境／工作心情 | 缺少可靠直接信号 | 仍 unknown，不读取私人聊天、任意工作区文件，不调用模型猜情绪；没有新增情境权重 |
| 重置与撤销 | 用户明确操作、单检查点 | 默认保留显式反馈；可选择同时清除。旧播放/旧成长不能穿过重置边界；撤销恢复检查点并尊重之后的新显式反馈，包括 0 |
| 平台切换账号 | Provider 登录状态和 discovery owner/revision | 旧候选、旧筛选、在途结果失效；同一 FishFM 数据目录内的本地曲库、显式反馈、Agent 偏好保留。现有 schema 没有按账号分表，不能声称本地偏好完全跨账号隔离 |

## 从操作到下一首、到模型筛选

当前歌曲反馈先校验播放实例，历史反馈仅可通过独立管理入口撤销；两者最终写同一 `user_track_feedback`，撤销保留 score=0。独立反馈版本保护多窗口并在重置／恢复后继续递增。这是同一事实来源的三条读取路径：

1. [本地选择](../../src/selection.mjs) 将 +0.25/-0.75 加入评分，禁播/不可播/冷却/排除当前先处理。喜欢是软优先级，不保证盖过其他合法因素。既有 LLM 排名加分、偏好与去重仍有效。
2. [种子选择](../../src/recommendation.mjs) 接收喜欢，排除少推荐和禁播，以真实平台关系召回候选。
3. [筛选事实包](../../src/persona.mjs) 从同一反馈表按本批候选逐曲读取，只把明确反馈附为 `liked/reduced`；未反馈及撤销不发该字段。原反馈总数和 Agent 艺人权重继续保留。模型返回候选序号后，仍须过生产解析器与本地硬约束。

成长沿 `growth_jobs` 去重、阈值/失败/重置/Session 门控 → 有限更新 Agent 曲目与艺人权重 → 进入模型 `taste.artists` 和下一首本地评分。画像文字不是这个决策链的替代品。

当前请求已经预留后才发生的新反馈，不能改写已发送的模型事实；会进入后续正常批次，本地排序读取当前反馈。没有因此增加一次模型调用、重试或后台任务。模型有了正确事实也不保证一定按用户预期筛选，真实效果继续由 #7/#11 评价。

## 本轮确认的缺口与最小修复

2026-10-18，在同批候选上先设 A 喜欢/B 少推荐，再对调为 A 少推荐/B 喜欢，原实现两次 `factHash` 完全一致：模型只知道喜欢 1 首、少推荐 1 首，不知道各是哪首。本地评分和种子读取本来有效，但未构成完整的模型输入路径。

现仅补充候选上的可选 `feedback` 标签和有反馈时的解释，不新增模型调用，不变更反馈存储、评分权重或播放规则。没有反馈时的字段与提示保持原样；旧数据库无需迁移。受既有最多 30 个候选、输入字节上限、token 预留、冷却、每日次数和共享预算约束，候选仍按原规则裁剪。输出 JSON 协议不变。

这项修复解决可复现的信息丢失，不是基于尚未发生的真人试用调参。流派、心情或“越来越懂用户”的收益仍未知。

## 复现与检查

```powershell
npm run research -- signals --out .tmp/preference-signals
node --test --test-timeout=30000 test/preference-signals.test.mjs test/feedback.test.mjs test/growth.test.mjs test/recommendation-pipeline.test.mjs
```

输出 `report.json/report.md`，已有目录不会覆盖。全部使用内存 SQLite、三首合成候选、固定时钟和 RNG；初始化后将候选偏好置相同中性值，隔离信号本身的作用，这不是改写生产默认值。无账号、音频、网络、真实模型或生产数据库访问。

16 项对照包括：相反反馈的模型可区分性、下一首变化、种子排除、用户与 Agent 数据分离、撤销、禁播优先、少推荐仍可播、跳过/暂停/故障/点播门控、达门槛跳过的弱正向权重、临时会话上限、重复成长去重、成长进入画像与下一首、重置边界、检查点撤销、静音经历及切号候选隔离。真实传输路径另由既有 recommendation-pipeline 回归核对逐曲标签确实抵达模型服务，下一首不增加模型调用。

真实人工标签尚未提供，#7/#11 的质量结果不能由这些合成对照替代。暂无证据支持新增长短期用户偏好表、情绪识别或更换推荐算法，相关提案保留后续研究。
