# 后续 feat：可见音乐人格、选歌回复与 token 用量

2026-10-03 用户最初要求先完成 N4–N7，再实施本 feat；随后提前结束 N7 长跑并明确要求直接开始 N9。未通过的长跑与对照保留，QQ 仍暂缓。本文设计由 N9 实现细化，状态统一在 PROJECT_PLAN。

## 用户期望

- 主界面默认收起输入曲库，设置里可查看和管理；这是界面层收起，不删除曲目，也不额外推断用户要求对 LLM 匿名化。
- 用户能看见大肥鱼的音乐倾向、推荐策略和变化，区分事实画像、本地策略与 LLM 总结。
- 每次自主选歌有简短回复，说明为什么选它，可展开依据。
- 少用 token，并显示插件实际用量，让调用频率和预算可控。

## 与当前工作衔接

N4 提供有来源的画像，N5 提供种子关系/评分/多样性，N6 先交付零 LLM 的确定性解释，N7 验证自动流程新增 LLM 请求为 0。本 feat 在这些基础上增加可选低频总结，不把 N4–N7 改成逐曲模型调用。

主面板以当前播放、大肥鱼偏好、策略和最近回复为主，输入曲库默认收起；明确入口转到设置的“输入音乐”。隐藏不改变初始化、禁播、点播权限或独立保存的用户环境/Agent 偏好。

| 内容 | 依据 | 展示约定 |
|---|---|---|
| 已观察偏好 | 有效自主经历及有来源的特征 | 覆盖率、样本量和更新时间 |
| 推荐策略 | 探索率、候选来源、评分/多样性参数 | 可查看和调整明确设置 |
| LLM 总结 | 对事实画像的低频归纳 | 标明模型总结、生成时间和实际 token |
| 选歌理由 | 当前决策的来源、评分和约束 | 短回复可展开，不编造音频理解/情绪 |

首版 LLM 总结只作展示；若以后让其修改选歌参数，另行定义有界结构化结果和验收，不用自然语言覆盖约束或长期 affinity。

## 低 token 方案

每首回复由真实决策与已缓存画像生成，例如“这次想探索一首相近的新歌，它与我最近偏好的艺人有关。”详细依据按需展开，不每曲请求 LLM，不持续向主聊天注入音乐状态。

总结默认由用户明确触发。可选自动更新只在足够新经历且超过冷却时运行；建议起点为 50 次新增有效自主收听、至少 24 小时，并允许关闭。实施时验证这些参数，不视为已启用行为。

输入优先用有来源的聚合画像、覆盖率、策略和变化摘要，不发送整份曲库/完整历史。首版可限制输入 1500 tokens、输出 256 tokens，使用实际模型的限制方式验证；同一画像/策略版本复用缓存。失败有限重试，预算不足保留旧总结和本地解释。

不足的情绪、流派或人格数据保留未知；平台账号推荐不称作 Agent 独立风格。没有可靠标签时只描述歌曲/艺人倾向。

## 用量显示与预算

- 每次插件主动模型调用记录功能、模型、时间、结果与返回 usage；拆分模型实际支持的 input/output/cache/reasoning 字段。
- 显示本次、今日、累计用量与请求次数，提供日预算和单次上限。未返回 usage 时标未知，不以字符估计冒充真实 token。
- 分别显示“本地选歌/回复：0 次 LLM 调用”和“人格总结：实际消耗”。未启用总结且代码没有主动模型调用时，直连用量可为 0。
- 主会话静态工具描述及用户主动询问音乐的对话开销另列；不能把未归因的共享上下文成本当作精确插件用量，也不声称没有间接成本。
- 并发使用原子预算预留/核销，失败/重试也记录实际返回 usage，跨重启不漏记或重复。凭据和完整输入不入账本。

优先核对实际 DSH 模型调用与 usage 契约；接口未验证时保留不可用状态，不隐式换供应商或另装代理演示。

## 完成标准

1. 主界面默认收起输入曲库，设置仍可查阅/管理；既有播放、暂停、来源和账号行为保持正确。
2. 事实画像与 LLM 总结有明确标识、时间、依据和数据覆盖。
3. 短回复对应同一 decisionId；手动播放不伪装成自主推荐。
4. 逐曲回复不新增模型请求，总结仅在授权触发、冷却和预算允许时运行。
5. 实际 usage 与账本可对照，缓存/失败/重试/并发/重启不漏记或重复，未知不报 0。
6. 约束、暂停、用户设置和长期偏好不被总结覆盖；收起视图不删除数据。

在 N4–N7 最终契约上细化 UI 与模型接入。执行顺序保持先补既有功能，再做本 feat。
