# QQ 音乐与双平台播放接入方案（提案）

2026-11-17 修订。本文规划 QQ 接入、双账号登录与播放来源选择。实施状态统一维护在 [开发状态](../PROJECT_PLAN.md)，现行产品行为和接口仍以 [MVP](../MVP.md)、[控制契约](../CORE_CONTRACT.md) 为准。

首版建议采用两个账号独立登录、一个自动播放来源、一条播放队列。默认来源为网易云，用户可以选择 QQ 音乐。两边的歌曲都可以明确点播，自动选曲按所选来源执行。本文的默认值、接口和迁移规则均为待实现设计。

## 2. 首版播放规则

### 账号、自动来源与曲目来源

这三种状态分别维护。账号状态描述能否调用平台。自动来源决定后续推荐从哪里召回和选曲。曲目的 `provider` 决定本次向哪个平台取链。

| 场景 | 计划行为 |
|---|---|
| 两边均已登录，自动来源为网易云 | 网易云召回、筛选与自动续播。QQ 保持登录，可导入与点播 |
| 两边均已登录，自动来源为 QQ | QQ 召回、筛选与自动续播。网易云保持登录，可导入与点播 |
| 仅登录 QQ，旧库没有来源设置 | 默认仍为网易云，界面提示选择 QQ 或登录网易云。由用户明确切源 |
| 选中来源尚未登录、过期或暂时失败 | 显示该平台原因。凭据仍有效且请求暂时失败时可保留该账号未过期的批准池，会话无效则使其推荐池失效。可用池耗尽后等待 |
| 用户点播另一平台的歌曲 | 按该曲所属平台取链，自动来源设置保持原值 |
| 历史上一首、历史前进 | 按历史条目的平台重播，沿用固定游标与用户优先规则 |
| 当前平台的一首歌无法取链或只提供试听 | 记录该平台该条目的不可播状态，按既有规则选择后续合格曲目 |

普通 `next` 耗尽批准池后的 `libraryFallback` 也限定在当前自动来源，避免从另一平台的输入曲库取歌。未指定曲目的初次播放、`chooseSelf` 与默认曲选择同样核对来源，曲库全库查询的 `firstTrack` 需经过该范围过滤。显式点播与历史导航继续按用户指定的曲目执行。

同名歌曲在两边保留各自的 `(provider, providerTrackId)`。首版候选池只接受一个平台，池内继续使用既有防重复规则。切源前后的同一录音仍可能作为两个平台条目重复出现，该限制在验收中单列。跨平台音源匹配、混合推荐与混合池的重复判定作为后续独立设计。已有历史和反馈继续按平台曲目键读取。

### 来源切换的生效时机

保存来源后，后续自动召回、筛选、预取和选曲使用新来源。已被 Core 接受为当前实例的歌曲继续按原来源完成解析或播放。暂停中的当前实例继续保持暂停。界面分别显示当前曲来源与后续自动来源。

切源时推进来源配置 revision 和推荐任务代次，取消旧来源的候选刷新、模型筛选等待与尚未交给当前实例的预取。迟到结果核对来源、账号与代次后才能提交。已产生的模型 usage 仍按实际结果入账，取消筛选也需完成账本终结。

切源操作保存设置并启动符合现有门控的补池工作。起播继续遵守 listening、自主权限、用户暂停、停止约束与既有安全事件规则。

## 3. 架构与运行时选择

```text
DSH 认证 RPC / UI
  └─ 独立 Node Core
       ├─ 自动来源设置 + 一条播放队列
       ├─ 网易云 Provider → 现有社区包 / 端点
       ├─ QQ Provider → qq-transport → QQ Worker
       │                              └─ 社区包公开入口
       └─ 选定曲目 → 所属 Provider 取链 → Playback → CDN / 本机音频
```

QQ 社区包处理平台协议，Core 决定播放哪首，Playback 接收短期资源并下载或打开。首版继续使用现有播放器和预加载机制。

### 候选运行时

| 路线 | 集成方式 | 需要确认的成本 | 规划位置 |
|---|---|---|---|
| 同包 `/serverless` | Worker 内调用公开 `handleRequest(Request, env, options)`，通过消息返回结果 | sealed 密钥、续期、取消和网络上下文。手机 QQ 的 HTTP 通道与 MQTT 通道实际能力 | 优先验证 |
| 同包 Node 根入口 | Worker 内加载 Koa 服务，内部 HTTP 调用 | 实际回环绑定、端口竞争、内部访问边界、stored 会话与设备仓库 | 能力不足时的备选 |
| `@sansenjian/qq-music-api/sdk` | 函数式调用 | 曲库与推荐覆盖不足，内部接口维护成本 | 缩小功能范围时重新评估 |
| 上游正式 Node client / 无监听应用工厂 | 公开函数注入网络与存储 | 依赖上游提供稳定接口 | 长期改进方向 |

`/serverless` 在本地 Worker 中执行。`3.3.7` 无中继时手机 QQ 可走 ptlogin HTTP 扫码，微信通道可用。QQ 音乐 App 通道需要 MQTT 中继。上游记录过不同运行方式的搜索与取链差异，P0 用相同账号与相同歌曲比较真实结果，最终入口由证据决定。

若采用 Node 根入口，须先解决监听参数的真实传递，再验证仅绑定回环。端口绑定失败采用有界重试。内部调用需限制可达角色并隔离会话读取，启动日志通过 Worker 独立输出进入脱敏诊断，Core stdout 继续承载 JSON-lines 协议。

### 生命周期与网络

QQ Worker 按 QQ 登录或数据操作延迟启动，并发启动共用一个初始化任务。启动和重建失败只更新 QQ 能力。网易云播放、状态读取和暂停沿用自身链路。

Worker 消息具有请求 ID、超时、取消和完成状态。退出时拒绝其全部 pending 请求。`provider.dispose()` 传递到 transport 与 Worker，Core 停用时等待清理。普通 Worker 异常可单独处理，资源耗尽仍按同进程故障评估。

每次请求携带网络配置版本与快照。QQ 内部 HTTP、鉴权请求及实际启用的 MQTT 连接需明确接入现有直连／自定义代理策略。取消应结束底层网络任务。仅让外层 Promise 提前返回不足以满足完成判据。网络适配范围限定在 QQ Worker 的请求上下文，旧请求保留发起时的配置，新请求读取新配置。

## 4. 登录、凭据与退出

两平台各自维护登录尝试、轮询代次、账号状态、凭据引用与运行时会话。QQ 的 `accountRef` 继续为 `fishfm/qq`，网易云沿用 `fishfm/netease`。SQLite 保留引用和非敏感状态。

| 运行时 | 计划保存内容 | 恢复与续期 |
|---|---|---|
| Node stored | token 与其对应的完整 `AuthSession` 经 `configureAuthSessionRepository` 适配到现有 DPAPI／Keychain。设备身份落在实例私有目录 | Worker 启动先恢复仓库，再验证账号资料。沿用上游 stored 续期机制并核对落盘结果 |
| Serverless sealed | 稳定的 `QQ_SESSION_SECRET`、sealed token 与必要的到期信息经现有加密存储持久化 | 重启复用密钥。按上游期限刷新并原子保存新 token。并发刷新共用任务，旧结果检查账号代次 |

Node 设备状态路径须从实例数据目录显式派生，避免默认工作目录下的 `.auth-state` 混用。P0 逐项核对设备仓库字段，其中的鉴权密钥材料也须纳入加密存储，并验证公开入口能否完成适配。账号退出时撤销对应会话并清理加密材料。设备身份按上游恢复要求独立管理。

登录仅在扫码成功、会话保存完成且账号资料校验通过后确认。`/login/status` 的 HTTP 200 空资料映射为会话无效。网络失败保留其真实错误。平台限制、设备名额和媒体权限分别显示，错误解释依据上游正文。

退出或切换账号只取消该平台的扫码、导入、取链和预取，并使该平台私有资源缓存失效。当前歌曲属于该平台时停止该实例，按既有进度结算后等待用户操作。当前歌曲来自另一平台时继续播放。活跃自动来源的账号变化还使当前推荐池失效，另一平台的纯登录状态变化只更新账号展示。

加密材料清理失败继续使用现有 `revoked / cleanupPending` 机制，重启后禁用残留会话。Worker 仓库同样需要收到停用与清理结果。sealed 模式的本地退出终止本插件使用，已签发 token 的服务端即时撤销能力按上游边界记录。

## 5. 来源设置、推荐缓存与旧数据

### 配置与并发保存

拟在现有 settings 表保存 `playback_source_v1`，字段为 `version=1`、独立递增 `revision` 和 `provider=netease|qq`。缺失或损坏记录按网易云读取，首次实际保存再落盘。

拟增加宿主认证 `fishfm/playback-source` RPC。空 payload 读取，写入接受 `provider` 与 `expectedRevision`。事务内比对版本，同值保持 revision，冲突返回 `playback_source_conflict`，客户端读回后由用户重新选择。返回仅包含来源配置与安全可用状态。

该 revision 表示来源配置，Core 的播放命令版本继续保护当前实例。后台任务同时携带来源 revision、候选代次和平台账号上下文。各自只取消其负责的工作。

### 首版复用一个活跃推荐池

候选召回、参考歌曲、模型候选、批准池、普通 next 回退和状态计数统一读取活跃来源。`discovery` 的 owner 只依赖所选平台及其账号身份，移除对另一平台登录状态的耦合。

首版切源清空活跃推荐缓存、已评候选与批准池，按新来源重新补齐。切回旧来源也需要补池，可能产生新的批量筛选调用，受现有共享预算与门控限制。这样可以复用现有单池调度，后续再根据切源频率决定是否保存分平台池。

候选容量、批准池容量、低水位、目标水位、TTL、失败退避与最近 50 次窗口继续按现行契约取值。来源切换不重置模型预算、历史、反馈或成长。来源值、来源配置 revision 和活跃参考输入需参与筛选有效性检查。

旧缓存缺少来源与新版 owner 的记录按派生缓存失效处理，保留账号、输入曲库、历史、反馈、成长与账本。显式版本化缓存 owner，使旧版读取能够拒绝新版派生缓存。回退版本前核对双平台曲目读取与来源默认值，并记录重新补池的影响。

全局用户环境和 Agent 长期偏好继续保留，两平台输入曲目按原平台键分开。自动召回的参考种子与输入覆盖计数按所选来源计算，说明文案分别标明当前参考范围和全局偏好。

## 6. 取链、下载与并发隔离

| 边界 | 计划规则 |
|---|---|
| 曲目身份 | 始终使用 `(provider, providerTrackId)`。QQ 归一化优先 `mid / songmid`，在进入共享层前补齐标题、艺人和毫秒时长 |
| 取链 | Registry 按曲目 `provider` 分发，各自携带所属平台会话 |
| 短期资源 | 缓存和 in-flight 请求除了曲目键，还核对所属平台账号代次。退出、换号后丢弃对应资源 |
| 下载 | 使用返回 URL 的真实 CDN。Windows 继续走 `MediaDownloads`，macOS 按既有平台能力打开。平台端点 Cookie 留在 Provider |
| 请求头 | 首轮验证匿名下载。如确需 Referer／UA，使用与单次资源关联的受限选项传递，避免依赖可被切源覆盖的全局当前平台 |
| 预加载 | 只准备既有选择器预测的一首后续曲。跨平台历史前进或点播仍允许准备该明确条目 |
| 取消 | 旧取链、下载和备用播放器只清理自身资源。已选同一资源交接给前台，沿用现有版本／宿主代次守卫 |

同一首歌曲的当前播放与预取继续复用合格资源。网易云与 QQ 的同数字 ID 分开缓存。并发下载各自持有随机临时文件与取消控制器。自然续播、跨平台点播、快速 next／pause 和预取交接一起验证。

QQ 取链结果先检查 `preview` 与 URL。明确试听结果拒绝进入整曲播放与有效成长，缺少标记的结果保留未知语义，真实试听识别能力按样本记录。

解析、媒体准备与中断恢复继续使用 [控制契约](../CORE_CONTRACT.md) 的各自预算。媒体下载与本机打开共用的 12 秒预算只属于准备阶段。现有恢复机制仍可按其原有次数与条件强制重新取链。未知 URL 到期时间按现有短期资源规则处理。

## 7. 角色、字段与错误适配

| 角色 | 上游路由 | 归一化要求 |
|---|---|---|
| `loginQr` | `/login/qr/key`、`/login/qr/create` | 通道来自 `/login/channels`，合成一个登录尝试 |
| `loginPoll` | `/login/qr/check` | 识别 `800/801/802/803`，成功材料按实际运行时保存 |
| `accountInfo` | `/login/status` | 校验 profile 与账号 ID。空资料显式失效 |
| `recentTracks` | 缺少对应路由 | 能力显示不可用。QQ 默认导入顺序为喜欢、歌单 |
| `likedTracks` | `/user/liked-songs` | `limit / offset / more` 分页，累计达到目标或真实结束 |
| `playlists / playlistTracks` | `/user/playlist`、`/user/playlist-detail` | 保留实际歌单身份与必要参数，支持本人不公开歌单 |
| `search` | `/search` | `keyword / type=song / page / limit`，核对单页上限与真实空结果 |
| `resolve` | `/getMusicPlay/:songmid` | 按 mid 取 `playUrl`，区分完整、试听、空链与失败 |
| `lyrics` | `/getLyric` | 原文 `lyric` 与译文 `trans` 接入已有 LRC 处理，ID 校验由平台规则提供 |
| 推荐 | `/user/daily-songs`、`/user/personal-fm`、`/song/similar` | 规范来源标签、同平台种子、失败来源与候选去重 |

共享账号状态机继续复用。允许为平台 ID 校验、曲目归一化和会话验证增加必要扩展点。QQ 适配器补 `getUserPlaylists` 与 `getDiscoveryTracks`，来源展示、批准池和事实生成接受经过校验的 QQ 来源。

transport 在共享 `call()` 丢弃 HTTP 错误正文前，映射为带安全详情的 `MusicError`。凭据失效可更新账号，设备名额错误展示实际限制，网络／上游失败保留账号。422 按角色与错误键处理，429 保留退避信息。取消与退出继续使用既有取消语义。安全详情仅输出固定字段与代码。

## 8. UI 与认证 RPC 的改动

登录、轮询、退出、导入与歌单 RPC 增加显式 `provider`，服务端仅接受受支持的平台值。旧调用省略该字段时沿用网易云。明确传入非法值时返回参数错误。前后端同时解除 `QUICK_LOGIN_PROVIDER` 的固定转发，QQ 歌单参数按实际标识校验。

客户端按平台分别保存二维码、登录尝试代次、轮询计时器、歌单选项、导入表单、忙碌与错误状态。响应还需核对平台及操作代次，A 平台迟到响应不能更新 B 平台。现有共享播放控制与状态 revision 规则继续使用。

电台设置中增加“自动播放来源”选择，展示两平台各自的登录与能力状态。来源可保存为暂时未登录的平台，界面随即展示对应登录／重试操作。登录完成只更新账号。用户选择自动来源后才采用该平台。

正在听、输入曲库和历史继续显示曲目所属平台。切源时当前曲来源与自动来源可以不同，分别显示已有事实。QQ 来源选项根据能力隐藏近期播放或显示缺失原因。多窗口来源写入使用独立 revision，读回失败保留用户可重试状态。

## 9. 预计改动范围与资源评估

| 模块 | 计划改动 |
|---|---|
| `src/providers/qq*.mjs`、`platform.mjs` | Worker／transport、会话适配、生命周期、字段归一化与平台扩展点 |
| `src/providers/contract.mjs`、`coordinator.mjs` | 保留平台身份，明确活跃来源与账号上下文 |
| `src/core-host.mjs`、`core.mjs`、`bin/fishfm-core.mjs` | 来源配置、注册／清理、任务代次、自动回退范围与资源缓存失效 |
| `src/discovery.mjs`、`approved-pool.mjs`、`recommendation-supply.mjs` | 活跃来源 owner、QQ 来源白名单、迁移与批次提交守卫 |
| `src/persona.mjs`、发现事实／记录模块 | 活跃参考与来源解释、模型结果有效性检查。旧兼容路径按来源审计 |
| `src/lyrics.mjs`、必要的 Playback 资源接口 | QQ 歌词、平台 ID 与实际媒体请求要求 |
| `src/ui/dsh-settings.mjs`、`src/ui/client/` | 按平台认证操作、独立 UI 任务状态、来源选择与故障提示 |
| 包清单、声明、当前规格与契约 | 固定依赖、实包核对、同步已实现行为与接口 |

每项实现按真实差异收敛文件范围。候选与模型任务仍只有一个活跃来源，逐曲调用继续为本地执行。新增成本主要来自 QQ 运行时、登录连接与缓存所有权处理。

P0 测量进程整体 RSS 增量、启动耗时、后台连接、取链耗时和退出残留。Worker 与 Core 同进程，RSS 报告注明统计范围。打包阶段测量含依赖的 tgz 与解包增量。包自身文件数、月下载量和源码语法检查不作为运行性能指标。

### 必须覆盖的回归场景

| 场景 | 核对结果 |
|---|---|
| 双平台同时扫码、交错轮询、取消其中一个 | 各自二维码、凭据与状态归属正确，另一平台可继续 |
| 两平台曲目使用相同数字 ID | 取链调用、缓存、反馈和历史仍按平台区分 |
| 网易云当前播放，QQ 下一首预加载。随后点播第三首并暂停 | 旧 QQ 下载／备用播放器清理自身，新歌曲与暂停保持权威 |
| 网易云播放期间 QQ Worker 启动失败或退出 | 当前播放、暂停和状态读取可用，QQ 失败可见且可重试 |
| 非活跃平台登录、退出或账号失效 | 活跃来源的候选和批准池保持有效 |
| 活跃平台退出／换号，旧取链、刷新或筛选迟到 | 对应任务取消，旧账号结果被拒绝，模型实际 usage 终结入账 |
| 当前曲保留期间切源、快速切回、两个窗口同时保存 | 配置冲突可见，当前实例按原状态完成，后台只提交最新来源结果 |
| QQ 来源的批准池耗尽 | 普通 next 只回退 QQ 输入／已知／喜欢曲，自动续播按原契约等待 |
| 无当前歌曲，输入曲库包含两个平台，自动来源为 QQ | 初次播放、默认曲和 chooseSelf 采用 QQ 范围，全库搜索仍展示各自平台 |
| HTTP 200 空账号、422 取链不可用、429、502 | 账号、媒体、限流和上游错误各自保留正确语义 |
| token 更新与退出／重启交错 | 撤销账号不被旧刷新复活，已保存会话能够恢复，未知结果可重试 |
| QQ 仅试听、歌词 mid、分页超过 100 首 | 试听不进入整曲成长，歌词校验通过，分页计数按实际返回 |
| 旧库、无来源设置、旧缓存、回退版本 | 默认网易云，派生缓存正确失效，持久业务数据可核对 |

离线契约与合成场景覆盖路由、状态和竞争。真实账号覆盖平台能力。隔离 DSH 覆盖安装、RPC 与生命周期。听音与性能按其实际环境单列。执行与改动相称的回归，检查通过后按剩余疑点安排验证。
