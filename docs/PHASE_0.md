# Phase 0：最小技术验证

更新：2026-09-27。**P0-01 生命周期与 P0-06 本地数据已有局部实测，关键路径均未完整通过。** 本阶段只证明关键路径，避免在未确认的接口上搭完整系统。

执行顺序和后续实现任务统一维护在 [开发路线](PROJECT_PLAN.md)。P0-04 先用自有或可合法使用的短音频验证独立播放宿主，再由 P0-02/03 提供平台资源完成真实播放和生命周期复测；不让平台与播放后端互相等待。

## 验证清单

| ID | 要回答的问题 | 最小实验与通过条件 | 失败处理 |
|---|---|---|---|
| [P0-01 DSH](spikes/P0-01-dsh.md) | 实际插件、事件、工具与退出接口是什么？ | 指定仓库/版本，最小插件接收真实生命周期；慢音乐请求不阻塞宿主；停用后正确清理 | 进行中：加载/卸载已测，事件/命令/慢请求未测 |
| P0-02 网易云 | 登录、种子、搜索、推荐和音频资源是否可用？ | 用户授权账号完成扫码/会话恢复；导入与搜索；用真实音频后端播放、暂停、恢复、换曲 | 记录各能力状态；近期来源失败可退歌单，音频失败不能算通过 |
| P0-03 QQ | 同上；近期常听能拿到什么？ | 独立完成与网易云相同的闭环；记录近期接口或实际 fallback 来源、数量 | 不死磕近期 API；登录/播放失败仍是双平台交付阻塞 |
| P0-04 Playback | 音频能脱离角色窗口和 UI 进程生存吗？ | 音频真实播放时分别隐藏窗、关闭窗、退出 UI 进程，确认继续播放与 track_end；验证暂停/静音/重连 | 修正音频宿主设计，不能把隐藏窗口成功等同进程隔离成功 |
| P0-05 Desktop | Tauri 小窗在当前机器是否可用？ | 透明、置顶、拖动、歌曲文本、控制、托盘恢复、位置保存；检查 DPI/屏幕变化与透明区域点击 | 记录具体失败组合；Core 可继续推进，UI 验收不能勾选完成 |
| [P0-06 本地数据](spikes/P0-06-local-data.md) | SQLite、凭据和会话恢复如何落地？ | 最小数据库迁移/重启恢复；确定凭据位置、退出清理；脱敏日志 | 进行中：迁移/重启已测，凭据后端与清理未测 |
| P0-07 运行边界 | 零新增 LLM、命令优先与多会话是否可验证？ | 记录请求计数入口；慢自主选歌期间点歌/暂停，旧结果不得覆盖；两个会话仅一条队列 | 调整事件串行化/版本控制与工具暴露方式后重测 |

P0-02 与 P0-03 的真实登录需要用户可用账号；准备好实验后再由用户完成扫码。无需收集用户明文 Cookie。推荐接口可降级，真实播放链路必须验证。

## 退出本阶段的条件

- DSH 接入路径及事件映射明确，音乐异常不会阻塞主任务。
- 两个平台都有真实登录/搜索/播放证据；导入不足与推荐能力缺失有可执行降级。
- 播放服务与可见 UI 的生命周期已分别验证，静音进度方案明确。
- 小窗、凭据、SQLite 与单一队列的宿主方案有结论。
- 证据足以确定代码布局与依赖；未通过条目仍明确列为未完成。

Phase 0 的短时验证不替代 [MVP A09](MVP.md) 的连续两小时运行验收。通过一次播放也不能推断所有账号、会员权限、曲目或系统均兼容。
