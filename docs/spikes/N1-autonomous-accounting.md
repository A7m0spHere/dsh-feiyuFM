# N1 自主续播与成长记账

更新：2026-10-03。**本轮 N1 完成标准通过**：修复后真实连续 5 次自然曲终/自主交接和成长对照完成，重启暂停、关闭自主与暂停保持已现场核对。完整运行态四开关/全部模式/到期约束的 A03 和长期 A09 不因此全部通过。

- `positionMs` 仅表示时间线位置；`effectiveMs`、`agentEffectiveMs`、`audibleMs` 分段累计。生产 Playback 用单调时间限定推进：超过 5 秒的观测缺口或大于经过时间 + 1 秒的位置跳变不补算；恢复起始位置不是新经历。
- 关闭自主听歌后的进度不增加 Agent 有效时长。成长采用 Agent 有效进度，并保留用户点播、失败与有效阈值门控；此前真实 Agent 片段保留，不把后续手动恢复的时间加进去。
- schema v4 在同一历史事务内加入成长待处理项。成长和处理标记使用同一事务（嵌套 savepoint），实例幂等；Host 启动重放未处理项。旧历史保留 `legacy-position`，不批量补写新成长；旧播放快照缺少分段计数时从 0 开始。
- 曲目明确不可播放时记录 30 分钟本地排除；自主解析失败最多尝试 3 个候选。网络/账号错误不作为曲目负面偏好。曲库都被过滤时等待，并保留选择原因。
- 选歌 PRNG 状态随 Core 状态持久化；重启继续选歌流，初始化人格种子不变。没有放宽禁播、权限或用户暂停。
- schema v4 不应由旧版本 v3 代码打开。部署前先用 SQLite 在线备份保存生产库，回退代码时配套恢复备份；账号凭据不随数据库入库。

前期验证：67 项专项测试通过，覆盖旧位置恢复、关闭自主后的有效时间、历史后崩溃重放、成长重复/事务回滚、不可播候选预算、随机流接续、v1/v2 升级、暂停/过期/重连和音频宿主契约。此前未完成的真实故障与自主曲终证据已在后续小节补充，不以离线事件代替真实曲终。

现场续播曾遇 `media_open_timeout`（已解析平台资源，WPF 12 秒未打开），原实现只替换明确不可播，导致电台暂停。后续修复将媒体超时/失败临时排除 5 分钟，仍使用单次最多 3 个候选预算；明确权限不可播仍排除 30 分钟。新增回归验证超时后能继续其他候选、不造历史、不惩罚偏好。实际用户 next 产生的手动段单独记录，不当作自主曲终。

后续复查修复 Host 控制延迟：命令先返回接受状态，媒体异步就绪；控制/快照绕过长账号任务，stdio 不等待上一条媒体操作才读取下一条消息。直接 Host 和独立 Core 进程的慢 Provider 回归都验证暂停及时到达、取消解析并无播放。等待真正就绪使用 `wait`，工具不把 resolving 当 playing。
