2026-10-04 用户澄清：下一首是请求换曲，不等于用户指定歌曲；希望低频 LLM 根据输入歌曲给出具体推荐，逐曲本地执行。原 N9 的展示总结与平台候选排序不足以满足目标；原 N10 重置保留输入曲库并重新初始化偏好，也不等于清空导入歌曲。本轮以本文件覆盖这两处产品定义，保留历史证据。

## 推荐链路

真实 Playback 宿主首次启用此版本时，推荐来源默认 LLM 歌单；保留显式可选的平台兼容模式。在 LLM 模式，网易云只搜索歌曲元数据、校验歌名/艺人和解析播放资源，不调用每日推荐、私人 FM 或相似推荐作为候选。模型没有通过核对的歌单时等待，不静默退回平台推荐或整个旧曲库。

一次模型请求发送最多 8 首按艺人分散的代表输入、最近喜欢/少推荐各 2 首、近期有效播放最多 3 首及探索设置。标题/艺人有长度限制，超 1500 UTF-8 字节时缩小样本；界面显示参考覆盖，不声称分析完整曲库或听懂音频。输出是 JSON：`summary` 为推测性推荐思路，`songs` 为歌名/艺人二元组，最多 6 首；128–191 输出上限时请求 3 首，默认 256 时请求 6 首。

Core 拒绝指令、网址、空/重复/超长条目和无效格式。平台核对先用已有元数据，必要时每首最多查询 10 条搜索结果，最多处理 6 首。准确歌名/艺人匹配可进候选；中文艺名前缀的拉丁别名可核对。多个录音只有作品匹配且平台艺人 ID 完全相同时才能采用默认匹配版本，并展示实际音源名；缺 ID、不同艺人、多义匹配仍拦截。模型指定了版本时要求完整标题匹配。找不到/登录失效单独显示，未经核对的建议不冒充可播放资源，音频权限仍由 Provider/Playback 验证。

Core 选择器仅同步读取模型已核对的缓存条目，保留禁播、暂停、探索开关、手动反馈、重复限制和真实成长规则。推荐歌单的思路与各条目核对状态可见；旧画像总结折叠并标记“仅展示”，不把它当作具体歌曲推荐。

## 用量与缓存

新增 `music_model_calls.purpose/facts_json`（schema v10）：旧账本标为 `persona-summary`，新歌单为 `model-recommendations`，同一账本对账真实 usage。展示总结与歌单共用日预算/最多 3 次尝试/并发锁；冷却各用途 1 小时，默认预算 4000，输出上限仍 64–256，歌单生成要求至少 128。相同参考/模型复用缓存，失败保留旧歌单并记真实费用，不自动重试或为每首歌请求模型。

可选自动更新仍默认关闭，开启后沿用上次成功生成的模型，画像改变、50 次新有效经历、24 小时间隔、冷却和预算都由 Core 在预留时复检。修复 Host 原来遗漏转发 `automatic` 的问题。生成模型歌单后自动更新对象为歌单，展示总结不覆盖这一选择。长期自动运行仍未验。

## 输入曲库清空与下一首

新增“清空输入曲库并重建偏好”的独立确认入口：清除 `user_environment/environment_sources`、积累偏好、待播队列及旧模型缓存，可勾选清除手动反馈；保留账号、曲目历史元数据、播放历史和 token 账本，不更改当前播放/暂停。命令响应立即返回新曲库投影，计数直接变 0。仅重置成长的旧功能改名，明确保留输入歌曲。

保存最近一次完整恢复点，撤销可恢复输入名单、来源事实、偏好及待播队列。新导入和成长可能被恢复点替换，UI 明示；事务失败同时回滚数据库和内存队列。清空后旧的异步歌曲核对结果不能重填缓存；缺少有效参考输入时拒绝模型请求。

`next` 记录推荐器选择者及 `selectionTrigger='user-next'`，保留来源/评分/同一 decisionId；`requestTrack` 才是指定歌曲。暂停不因换曲撤销，选中本身不制造成长。旧版已保存的 user 选曲没有触发来源，标记来源未区分，不倒改历史。
