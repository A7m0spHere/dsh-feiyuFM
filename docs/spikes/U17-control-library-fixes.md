# U17：播放控制、全库搜索与平台错误反馈

日期：2026-10-08。仅源码、离线测试和隔离浏览器；生产未重载，npm 未发布。

## 问题与改动

- 原平台操作与用户命令共用 busy，导入可能阻止暂停达 120 秒。现在平台请求独立占用、取消，暂停/切歌与轮询继续；平台响应不能覆盖其间发生的播放命令或较新播放修订。导入时清库/恢复入口仍互斥。
- 原 Host 固定返回前 300 首，客户端的分页和搜索只覆盖该子集。新增认证 `fishfm/library` 与 Host `library` 查询参数，SQLite 对标题/艺人/ID 全库检索，每页默认 12 首；查询和分页边界验证、字面量搜索、越界回退和零结果均有覆盖。返回独立 firstTrack，空查询结果不妨碍手动开始听歌。
- 查询有独立代次与取消控制器；旧查询、旧轮询、旧平台响应不能盖回新页。定期状态请求携带当前查询，清库后页码收敛。
- 平台错误按具体动作反馈，补查 Core 成功才确认恢复；传输失败、Core 不可达、可达的业务失败分别处理，普通读取失败不制造登录失败状态。
