# N22：网易云先推荐，LLM 再挑歌

2026-10-07。用户明确收拢产品目标：输入参考歌曲后，先从网易云拿到推荐歌曲，再交给 LLM 筛选，让用户看到大肥鱼在选歌、听歌。此指令修订 N11 的“模型直接提出歌名后搜索核对”，以及 N15 的“筛选只做加分、未入选仍可播”。

## 现在的流程

1. 参考歌曲沿用现有网易云曲库/歌单导入；输入记录、账号和播放历史保留。以输入歌曲与已有反馈选择种子，复用网易云相似歌曲/每日推荐等真实候选召回。
2. LLM 只接受平台返回的候选、参考歌名/艺人、偏好与来源线索，返回候选序号、顺序和简短理由。平台没有歌时不调用模型；模型不能把自造歌名加入播放名单，也不声称感知音频。
3. 默认 `filtered` 模式只有入选歌曲进入自动播放池；禁播、不可播、重复冷却、暂停、静音与用户点播/下一首继续由本地 Core 执行。换曲不发模型请求。
4. 自主听歌开启时，导入后、启动后、平台候选变化或低水位按需补一批；关闭或“今天停止”不再自动发模型请求，仍可手动挑歌。复用已保存的模型；首次可从 DSH 已配置模型初始化，不再要求先生成画像总结。批量调用仍有 15 分钟冷却、每日 12 次和共享 token 预算。
5. 普通换批失败保留同账号、未过期的上一批真实平台歌曲。更换账号、清空输入或重置候选时失效。模型明确没挑中任何歌曲可保存空结果，不伪造候选，也不在同批次循环请求。

新模式把筛选后的歌单作为一个播放池，避免一批全是新歌时因熟悉/探索池随机分流而空选；探索率作为筛选偏好，0/关闭仍禁止自动选择陌生曲。选择后的新/熟悉分类仍真实记账。用户主动下一首保留输入曲库回退，自动续播没有这个回退。

## 主界面

“大肥鱼的歌单”只展示当前找歌/挑歌/准备好的状态、歌曲、艺人、简短理由和“找一批歌/换一批”。歌曲可直接点播，超过六首再展开；“大肥鱼说”按本次真实入选理由解释。主面板不再展示本地事实标签、规则选歌、推荐来源切换、模型生成后 3/6 核对等混合概念。

模型选择、用量、预算与调用明细放入默认折叠的“推荐设置”。旧画像总结/直接生成歌名的入口不出现在本界面；旧数据库记录与内部兼容代码保留，真实宿主首次加载新流程时迁移默认模式，原曲库、反馈、历史和开关不清空。

## 并发与失败

每批候选有本机 revision 与账号归属摘要。revision、候选完整元数据只存在预留记录里，不发送给模型；模型只得到挑选所需事实。候选在请求期间变化时，旧输出不能替换新歌单，但实际用量仍入账。账号变化不能复用其他账号的歌单。

请求模型期间暂停仍立即生效，完成筛选不会解除暂停。默认输出 256 tokens 时提示最多挑六首；64/128 输出上限会相应减少推荐数量，避免要求模型在过小输出中塞入十二首。返回最多保留十二个有效、去重的候选序号；错误索引不能构成歌曲。

当剩余额度不足以容纳整批时，减少发送给模型的候选数量；保守预留仍是事实 UTF-8 字节 + 1024 + 输出上限，不调高用户预算，不把估算当精确 token。
