# N12 模型歌单核对修复

2026-10-04 用户报告“模型歌单暂时没有可用歌曲（no_candidates）”，要求修复，并明确提交信息保留 `feat:`、`fix:`、`docs:` 等英文前缀，标题及正文使用简体中文。

## 原因与处理

生产库只读检查：当前推荐来源为 LLM，11:43:42 生成的歌单有 6 首，核对通过 0 首，逐首状态均为 `not-found`；最近 30 分钟没有结束的播放记录，本次并非重复冷却。歌曲已生成，但选择器只读已核对的模型缓存，因此手动下一首没有候选。

`世末歌者` 模型艺人为 `COP / 乐正绫`，本地曲目 `429460239` 与平台搜索返回 `乐正绫 / COP`。旧实现将整串艺人和整串名称或单个艺人比较，导致同一名单的不同排列被拒绝。现按结构化艺人名单逐一匹配模型指定的全部艺人，忽略排列；缺少结构化名单时使用平台展示名单。保留 AC/DC 等带斜杠的完整艺人名。`洛天依` / `洛天依Official` 采用明确的名称映射，依据此次平台搜索元数据（艺人 ID `906118`，曲目 `404543406`）；不普遍删除任意艺人的 Official 后缀。

多个录音仍检查匹配艺人的平台 ID 集合，同名异 ID、缺 ID、漏掉模型指定艺人和未知别名不能通过歧义核对。模型混写创作者和演唱者而平台缺少其中一人的条目保留 `not-found`，不凭歌名猜测演唱者。

公开搜索复测遇到 HTTP 200 / 业务码 406，旧解析器把缺失歌曲列表当作空列表。网易云搜索现在校验业务码和结果结构：失败记 `lookup-failed` 并保留数字接口码，合法 `songCount=0` 仍是空结果；业务码 301 同时使已保存授权引用失效。没有请求平台推荐或重新生成模型歌单。

下一首提示区分未生成歌单、没有核对通过歌曲与已有歌曲被重复/播放规则排除。LLM `no_candidates` 的操作按钮改为调用实际核对 RPC 的“重新核对歌单”；其他已连接错误显示“刷新状态”，断连时显示“重新连接”。核对响应同步画像中的歌单投影。
