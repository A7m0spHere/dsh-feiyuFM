# N25：最近播放窗口与多批有效入选池

2026-10-21。用户报告二三十首内容易重播，随后补充“4–5 首左右就出现重复”。本轮按用户确认的 50 次播放窗口、100 首多批待播池和缺歌最久未播降级实现。当前状态只维护在 [PROJECT_PLAN](../PROJECT_PLAN.md)，控制规则见 [MVP](../MVP.md) 和 [CORE_CONTRACT](../CORE_CONTRACT.md)。

## 原因与修订

只读查询日常数据库的最近 120 条历史，在最近 45 条中确认一个样本：同一平台 ID、同一筛选批次，中间隔 5 首再次播放；两次结束相差 56.7 分钟。查询时参考曲库为 233 首、当前批次入选 10 首。公开材料只保留这些汇总，不提交歌曲、账号、曲库或数据库。

旧实现只有 30 分钟硬冷却；最近 50 条历史是 6 小时评分窗口，时间过去后旧歌仍可被偏好和模型排名重新选中。当前批次替换也让自动候选一直局限在少量歌曲；普通 next 的直接队列分支还绕过了选歌器。

## 产品行为

1. 最近 50 个真正开始的播放实例按顺序保留，跨暂停、跨天和重启；短暂成功开始后的跳过也计入。未开始的失败／只选中未播放／零有效增量的位置变化不入窗。同一实例恢复不重复登记，遗漏 started 时首个有效进度可确认开始。
2. 普通 next、推荐队列与自动续播共用策略。先选窗口外且满足原时间冷却的歌曲，再放宽时间冷却，最后只在缺歌时按最久未播顺序续播。偏好和模型排名不能抢过降级顺序；当前／刚播完同曲、禁播和不可播不放宽。明确点播可重播，实际开始仍入窗。
3. 同账号、未过期、已经模型批准的多批歌曲累计最多 100 首，按平台 ID 去重；新批准替换同 ID 的旧批准，来源、rank、reason、modelCallId 与原 expiry 都保留。过期先清理，容量超限淘汰最早批准。
4. 候选送入模型前也排除最近窗口和当前曲目；沿用现有调度、并发门控、次数和 token 预算。自动播放不混入未入选参考曲库；用户 next 的原有曲库回退仍可用，回退也优先避开近期播放。
5. 当前批次歌单和“近期发现”仍只展示该批。界面另显示待播池总数、窗口外可选数和近期暂避数，真实降级时用现有说明区域提示“可用新曲不足，先重播较早的歌曲”，不弹窗或发消息。

## 存储与并发

只增加 `recent_playback_v1`、`filtered_playback_pool_v1` 两个有界版本化 settings，不增加表或 schema 版本。旧库只从有进度历史／已开始当前实例恢复播放顺序，从当前可核验的有效入选批次兼容读取；不从原始候选或旧调用账本反推批准。

成功筛选的待播池合并、当前批次和账本完成状态在同一事务内提交；重复完成不重新批准，写失败整体回滚。现有候选代次校验之外，再核对当前账号指纹；账号切换、清缓存、偏好／输入重置及撤销重置均清理待播池，播放窗口随真实历史保留。原子开始登记与 Core 状态一起保存。

`snapshot.discovery` 与 `persona.recommendationPipeline` 可选添加 `playbackPool` 计数，旧客户端可忽略；新客户端连接旧 Core 时不显示缺失项。`local-v6` 的 `lastSelection.detail.repeat` 记录窗口长度、降级原因和最近播放距离。模型工具、模型输入上限、成长资格和反馈权重未扩大。

## 验证与复现

- 固定输入复现“隔 5 首、56.7 分钟后”的高偏好旧曲，存在新曲时不再选回；跨天仍保持窗口。
- 100 首候选用替身事件加速模拟 200 次开始，无最近 50 次内重复；3 首小池按最近开始顺序轮转，不被高偏好分数劫持。
- 文件数据库重开、暂停恢复、明确点播、推荐队列、短暂跳过、未启动媒体失败、位置跳转和漏 started 事件分别覆盖。
- 多批累计／100 首上限／最新同 ID 批准／原到期时间／账号隔离／当前批次投影／重置／迟到完成／重复完成／写失败事务回滚分别覆盖。

结构化附件见 [N25 结果](assets/N25-repeat-policy-results.json)。最终全量 **561 项：558 通过、0 失败、3 项真实媒体跳过**，测试并发限制为 2；本轮新增 22 项回归，旧冷却断言按新策略修订，RNG 用多个可选曲验证。原生媒体另在隔离宿主实测，**20/20 通过、真实模型请求 0**。164 模块检查、构建/debug smoke、npm 包白名单（4885 文件）通过，105 份文档零坏链接。完整 A01–A10 状态不因本轮局部验证全部提升。

## 交付边界

没有主动重载日常实例、暂停用户播放或直接写日常数据库。本轮只读核对时发现日常进程期间已发生重启，并已存在新版窗口和待播池设置，读取到 17 首有效入选曲、50 个窗口实例；没有合成测试批准混入。进程具体加载了哪些中途源文件无法追溯，最终提交完整加载仍记 unknown，不能把该观察记为原生 Desktop 正常退出／重开验收。

源码与生成客户端同步交付，未发布 npm。若只有一首刚播完的有效曲，仍等待或由用户明确点播；“缺歌保持续播”不能覆盖禁播、不可播和当前曲目限制。历史已被覆盖的入选批次不能凭空恢复，首次升级不保证池中立即有 100 首。

真实网易云音频、长期推荐体验、日常原生 Desktop、macOS 与跨设备仍按项目计划保留未验；不恢复已取消的两小时连续观察。
