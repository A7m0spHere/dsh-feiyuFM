# N18：P2——进度平滑与歌单生成的关系事实

日期：2026-10-05。范围：`src/ui/client/presentation.mjs`（插值纯函数）、`src/ui/client/components.mjs`（`useSmoothProgress`）、`src/ui/client/panel.mjs`、`src/ui/client/floating.mjs`、`src/persona.mjs`、`src/core-host.mjs`。

## 一、进度显示平滑（P2-6）

状态每 ~2.2 秒轮询一次，直接渲染进度条会让界面"跳格"。新增纯函数 `interpolatedPosition`：以最近一次**服务端**进度为锚点，播放中按本地时钟插值推进；暂停立即回到锚点（不虚增），切歌丢弃旧锚点，插值不超过曲目时长；时长未知时不设上限。主面板与悬浮条共用。

关键点是纯函数放在 `presentation.mjs`（无 React 依赖），行为可直接单测：播放推进、暂停归位、切歌不串、封顶、无锚点回退。

## 二、歌单生成喂入关系事实（P2-7）

歌单生成的 `factBundle` 新增 `relations`：从相似图取度最高的至多 4 首输入歌，每首附最多 2 首"常一起出现"的歌（同歌单/共同艺人/连续播放）。提示词明确要求"优先顺着关系事实延伸，而不是只按歌手名字猜测风格"——把生成从"看歌名猜风格"升级为"看结构推理"，与 N15 的候选筛选方向一致。

边界：只发歌名/艺人，绝不发平台 ID（测试断言 `netease:` 不出现）；超字节上限时按价值裁剪——先丢最近播放，再丢关系事实，最后才减参考歌曲；没有图时不编造 `relations` 字段。
