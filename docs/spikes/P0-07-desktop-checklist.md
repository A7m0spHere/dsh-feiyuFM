# P0 日常 Desktop 最小人工验收卡

对象：人工选择的 P0 修复候选包。0.1.1 临时演练包不代表已发布；源码分支、npm 已发布版本与 Desktop 实际加载版本分别记录。本轮只准备清单，以下日常结果均为 `unknown`，不能用隔离 Web profile 或自动化回归代填。

操作前记录日期、Windows／DSH 版本、实际 profile、`DSH_HOME`、候选包版本／SHA-256 与代码提交。保留现有 `fishfm` 数据目录及原始 DPAPI 凭据；不清库、不重置画像。若日常账号已授权，不为测试二维码而退出账号；首次二维码／授权两项可在用户自行选择的独立 Desktop 验收 profile 中完成，记录实际 profile。

| 状态 | 步骤 | 最小操作与通过标准 | 记录 |
|---|---|---|---|
| [ ] | 1. 实际安装来源 | 在插件管理器确认来源是候选 tgz／npm 包，只有一份启用；同时核对该 profile 的 package.json／锁文件实际来源与已安装包版本，不只看“0.1.x”显示名。完整退出托盘并重开，确认加载了该候选 | 来源、版本、摘要；不用复制整份配置或凭据 |
| [ ] | 2. 二维码显示 | 打开肥鱼电台 → 电台设置 → 音乐平台；平台读取结束后有可点击的“扫码登录”，点击出现二维码。单独曲库仍在读取时登录入口也应可用 | 入口／图片是否出现；仅记录耗时、阶段和错误码，不保存二维码 key／链接 |
| [ ] | 3. 扫码授权 | 用户用网易云 App 扫码并在手机确认；桌面从等待／已扫码进入授权结果，失败可按明确提示重试 | 成功／取消／过期及实际错误码；由用户操作，不代填 |
| [ ] | 4. 账号校验 | 经真实账号校验后显示已登录及可用的导入操作；二维码轮询成功本身不算账号校验通过 | `authorized` 或校验错误码；账号 ID 仅在本机核对，外发前遮盖 |
| [ ] | 5. 歌单导入 | 选择用户确认的小歌单或当前导入来源，执行一次导入；界面显示实际数量，曲库随后可查询，不能因初始化曲库延迟丢掉平台登录 | 来源类型、数量、结果；不外发歌单私密信息 |
| [ ] | 6. 实际播放 | 手动点播一首用户有权限的曲目，确认原生 Desktop 真实播放、进度增长；声音开启时由用户确认出声。记录会员／版权／资源错误，不能把状态文字单独算实际播放 | 真实进度、是否出声、错误码；不上传音频或媒体 URL |
| [ ] | 7. 重启保持 | 先暂停，再从托盘完整退出、重开同一 profile；核对安装来源、曲库／偏好／暂停保持。授权仍有效时正常恢复，过期时明确提示重新授权，不能卡“读取中” | 保持结果、是否需要重新授权及原因 |

P0 登录部分的人工通过需完成 1–5、7；整体 Desktop 交付还需第 6 项真实播放。未执行或证据不足保持 `unknown`，失败记录实际路径，不靠清库、伪造授权或增加超时得到通过。人工结果统一回填 [PROJECT_PLAN](../PROJECT_PLAN.md) 的 P0 行，并链接 [收尾证据](P0-07-initial-state.md)。P1 轻量引导保持独立，未开始。

先前临时加密凭据副本保持原状；清理需经过授权与审查，本轮不删除、改名、覆盖或改用其他工具清理。
