## 有效进度阈值

一次收听要计入，必须同时满足：

| 条件 | 规则 |
|---|---|
| 进度 | `effectiveMs ≥ min(30 秒, 曲目时长 × 50%)`；时长未知时用 30 秒绝对下限 |
| 结束原因 | `ended` 或 `skipped`（跳过计权减半）；`error` 一律不计 |
| 选择者 | **必须是 Agent 自己选的**；用户点播完全不计入 Agent 偏好 |

"用户播放不更新 Agent 听歌偏好"是 MVP 明文要求，因此它是硬门控而不是权重调整（测试专门断言用户点播后 affinity 一位不变）。

## 权重与有界更新

| 参数 | 值 | 理由 |
|---|---|---|
| 单次上限 `maxStep` | 0.03 | "有限更新"：一次收听不应主导偏好 |
| 跳过权重 | ×0.5 | 听了但没听完，证据弱一半 |
| 静音权重 | ×0.6 | 静音经历是真实经历，但不是"听到" |
| 递减 | `headroom × 0.25` 同时封顶 | 越接近上限步长越小 |
| 上限 / 下限 | 0.95 / 0.05 | 保留继续演化的空间 |
| 衰减 | 每天向 0.5 回落 2% | 时间本身会稀释偏好 |

**永不下降**：跳过不等于讨厌、平台失败不算负面偏好，因此成长只做非负更新（测试断言 `after ≥ before`）。正因如此，**衰减**是防止偏置单向累积的必要机制，而不是可选优化。

## 防自我强化（A06 的核心要求）

"选中就加分"会自我强化：选择→曝光→加分→更易被选中。三重约束打断这个循环：

1. **有界步长**：接近上限时步长按 `headroom × 0.25` 收缩。
2. **时间衰减**：闲置会向中性回落，长期不听的偏好不会永久占据高位。
3. **T2 的重复惩罚与冷却**：刚播过的曲目直接退出候选。

受控测试：连续 200 次有效收听，affinity **始终未达上限**（`< 0.95`），首步增量大于末步增量，累计增量小于 1.0——即"听 200 次也不会把量表走满"。

## 非复制用户（A06）

受控轨迹测试：两首歌给用户 `play_count` 分别为 99 与 1，但**只让第一条轨迹的 Agent 反复听那首"用户听得少"的歌**。结果：

- 两条轨迹（种子 101 / 202）成长后互不相同 → 经历确实塑造差异；
- 被听的那首 affinity 高于同轨迹中未被听的曲目 → 听谁就长谁；
- 用户点播 99 次的那首**没有**成为 Agent 最爱 → 人格不是用户历史的副本。

## 本轮修掉的两个真实缺陷

1. **选择器丢掉了曲目元数据（严重）**：`listFamiliar` 只返回 `provider` + `providerTrackId`，于是 `durationMs` 丢失，`qualifiesAsListen` 只能退回 30 秒绝对阈值——**短曲目永远无法计入成长**，成长在产品路径上实际上不会发生。已改为从 `tracks` 表恢复标题、艺人与时长。（只有把成长接到真实宿主路径上、并检查产生的 delta 才暴露出来。）
2. **后到的导入没有偏好行**：`initializeAgentPreferences` 原本"已有偏好即完全 no-op"，导致**第二次导入的曲目根本没有 preference 行**，只能按中性 0.5 参与评分，且艺人均值也漏掉它们。已改为**只补写缺失行、绝不覆盖已有行**——重启仍然一位不变（原 T1 测试继续通过），新导入也能进入人格。

## 仍未验证

- **真实时长与真实进度**：本轮 `durationMs` 与 `positionMs` 由测试驱动（600 ms 合成曲目）。真实平台时长、拖拽跳转、暂停后再续播对 `effectiveMs` 的影响待 P1/P2 真实音频复测。
- **衰减未接入调度**：`decayPreferences` 已实现并有测试，但尚无定时维护任务调用它（还没有长驻调度器）。当前只有显式调用才衰减——**诚实地说：现阶段偏置不会自动衰减**。
- **静音权重 0.6 / 步长 0.03 / 衰减 2%** 均为首版取值，无真实听歌数据支撑。
